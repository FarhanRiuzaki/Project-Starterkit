## Keputusan aktif Sesi 1

### DEC-009 — mandat dan target rilis pertama

**Status:** diputuskan dalam perencanaan. **Sumber:** instruksi role pemilik dan jawaban eksplisit “Template siap dipakai lokal; kapasitas belum ditentukan”.

Produk: prioritaskan reproduksibilitas setup, contoh projects dan fondasi akses/UI yang sudah ada. Product Lead menggabungkan keputusan produk dan arsitektur; Designer, Developer, QA tetap memegang bidangnya.

Teknis: pertahankan stack dan boundary yang ada. Staging, provider nyata dan operasi produksi menjadi tahap lanjutan. Alternatif memasukkan seluruh deployment/integrasi sekarang menambah dependency akses dan verifikasi yang tidak dibutuhkan target lokal.

Konsekuensi: OPS-001 menjadi P2 untuk tahap berikutnya; dukungan adapter existing tidak dihapus. Tidak mengklaim template siap produksi. Konteks team.md dari sesi Core akan diselaraskan melalui PL-002.

### DEC-010 — MVP berupa stabilisasi, tanpa fitur domain baru

**Status:** keputusan Product Lead untuk scope kerja saat ini.

Produk: pertahankan auth/account/users/RBAC/audit/dashboard, UI bersama dan contoh projects. Tunda tenant, billing, signup baru, server upload, queue dan domain tambahan. Alternatif menambah modul contoh kedua tidak memperkuat bukti yang belum terpenuhi: projects sudah menguji pola perluasan.

Teknis: zod contracts + API registry + schema/migration + thin page/prefetch + query keys + tests adalah kontrak perluasan minimum. Tanpa database/layanan baru. Mail fire-and-forget dan keterbatasan rotasi encryption key tetap didokumentasikan; bukan janji delivery/recovery produksi.

Konsekuensi: Developer berfokus pada temuan yang direproduksi, bukan refactor umum. Permintaan baru mendapat task/AC dan dampak target sebelum implementasi.

### DEC-011 — timeline bersyarat dan bukti kandidat

**Status:** target perencanaan, bukan komitmen tanggal atau persetujuan rilis.

Skenario awal tanpa implementasi perubahan filter: 7–10 hari kerja bila Developer penuh waktu, Designer/QA masing-masing 2–3 hari fokus/minggu, Product Lead tersedia. Kapasitas aktual belum diketahui. M0 selesai, tugas Ready berjalan paralel, koreksi dibatasi anggaran awal 1–2 hari Developer lalu diestimasi ulang jika melebihi.

Gate: QA menilai revisi kandidat dengan pinned runtime, check/build/budget/E2E dan quick start independen. Bukti Sesi 1 (1.528 tes, Bun host 1.4.4) adalah diagnostik; tidak mengubah verdict QA. Riwayat full E2E dengan dua gagal dan retest tetap disimpan apa adanya. Headroom `/users` hampir nol: target kerja 245 kB, gate resmi tetap 250 kB; jangan menaikkan budget.

Konsekuensi: tanpa kapasitas tidak ada tanggal komitmen. REL-001 harus merekam go/no-go, risiko, owner dan mitigasi. Gagal akses/data/setup/flow inti tidak dapat dilewati untuk rilis lokal. Dampak permintaan filter dijelaskan di DEC-014.

Urutan: FIL-DES-001 → FIL-DEV-001 → FIL-QA-002; QA menyusun skenario bersamaan dengan desain. Review dan paket handoff dilakukan sekarang. Angka ini bersyarat hasil desain/diagnosis, bukan janji atau klaim penugasan sesi lain. Tidak ada kode UI diubah oleh Product Lead dalam review ini.

### DEC-017 — sidebar filter Bifrost, auto-apply dan multiselect

**Status: keputusan aktif dari instruksi pemilik terbaru**, menggantikan ketentuan modal/scalar/draft-Apply DEC-014 dan spesifikasi FIL-DES-001. Referensi pengguna: CleanShot 2026-11-08 at 18.42.38@2x.png (bentuk open) dan 18.44.01@2x.png (expanded vs collapsed rail). Kode/tes lama tidak dihapus sebagai riwayat; hasil lulusnya tidak membuktikan kebutuhan baru.

Produk: default collapsed berupa rail vertikal floating kanan dengan toggle, ikon, label Filters dan badge; expanded menjadi sidebar berkelompok seperti referensi. Desktop nonmodal tanpa scrim yang menghalangi hasil; Designer menentukan ukuran/offset dan penanganan fokus/coverage serta phone variant. Checkbox mendukung banyak pilihan dalam satu group; pilihan langsung berlaku tanpa Apply, panel tetap terbuka. Clear all langsung menghapus kriteria filter. Tidak ada perubahan radio untuk form domain, theme, density atau saved-view picker; perubahan checkbox hanya field kategori pada filter list. Search tetap text; Roles yang hanya memiliki search tidak diberi kategori palsu. Tidak menambah Outcome/Team/Model ke domain starterkit atau angka facet dummy. Facet count server belum diminta sebagai fitur terpisah.

Teknis/semantik yang diputuskan:

- OR di dalam group, AND antar-group. Tidak terpilih = tidak ada batasan group. Memilih seluruh status tetap mempertahankan checkbox/URL pilihan, meskipun hasilnya setara Any. Users dengan dua role cukup memegang salah satunya dan tidak terduplikasi.
- Gunakan nama key query lama dan **repeated parameters** untuk multi: `status=active&status=archived`, `role=Admin&role=Viewer`. Scalar lama tetap diterima sebagai singleton; jangan split comma karena nama role dapat mengandung comma. Browser canonical: dedupe exact string, sort UTF-16 code-unit ordinal stabil, append setiap nilai, omit group kosong; query keys/prefetch/views menggunakan bentuk canonical yang sama. Case-insensitive matching role yang sudah ada tetap dipertahankan.
- API menerima string atau array string pada field kategori: users role/status, projects status, permissions module, activity action, auth log event/method. Array maksimum **50 elemen raw per field sebelum dedupe**; input array kosong berarti tidak membatasi. Enum invalid/unknown, non-string atau >50 memberi 400 sebelum guard pada list GET. Scalar role/action bebas mengikuti batas existing 64 dan unknown yang valid tetap menghasilkan kosong, bukan kesalahan permission; empty scalar legacy tetap no filter, elemen array kosong ditolak. Jangan menambah global route atau migration.
- Normalisasi/SQL predicate dipakai konsisten pada list, count, CSV dan users bulk filter. BulkUserFilter role/status menerima scalar/array sesuai semantik yang sama; BulkUserBody.role untuk assignRole tetap scalar. Gunakan bound values, IN/OR/EXISTS sesuai query builder; jangan mengubah guard, rank, limit 1000 bulk atau cap export. Kontrak/schema docs dan tes query-check-order diperbarui.
- Checkbox: commit segera, history push per aksi pengguna, page 1, tanpa close panel. Search: debounce **300 ms** sesuai keputusan Designer (hanya filter baru; consumer QueryInput lain tidak diubah), Enter/blur/collapse flush nilai terbaru; history replace untuk search. Pending debounce dibatalkan pada Clear all/Back/saved-view/external state, tidak boleh memunculkan filter lama lagi. Rapid toggle harus menggabungkan state terbaru, bukan closure URL stale. Sort/pageSize/header date/refresh tidak ikut dihapus oleh Clear all; text search dan semua category group dibersihkan.
- Badge adalah total opsi checkbox terpilih + satu untuk search nonempty; header date range tidak dihitung. Chip per opsi dapat dihapus tanpa menghapus sibling pilihan; group summary menunjukkan pilihan aktif, tidak ada draft Applied/Unapplied. Loading/error hasil tetap recoverable dengan data sebelumnya sesuai query yang benar; error GET tidak me-reset checked state atau membuka/menutup panel sendiri.
- Back/view/deep link lama dan baru harus roundtrip server prefetch→browser; helper yang masih memakai sp.get/Object.fromEntries harus diaudit agar repeated values tidak hilang. Named saved-view query server dinaikkan dari 300 menjadi **4096 karakter** (kontrak DTO/body, tanpa migration karena kolom text); preference cookie tetap **300 karakter per remembered view**. Jangan memperbesar cookie atau men-truncate pilihan. Di atas 300, hapus remembered view lama untuk halaman itu dan jelaskan bahwa view ini tidak diingat otomatis tetapi dapat disimpan sebagai named view. Di atas 4096, URL/filter tetap bekerja, Save view menjelaskan batas secara recoverable dan tidak mengaku tersimpan. Canonical ordering menghindari view duplikat karena urutan checkbox.
- Static group yang lebih panjang boleh Show more/less menurut Designer. Role options tetap server-paged/searchable; pilihan yang sedang tidak ada di page opsi tidak hilang, dapat dihapus. Error lookup tidak menghapus pilihan atau dianggap hasil kosong sah. UI menolak pilihan ke-51 dengan alasan, selalu boleh uncheck/Clear.

Audit feasibility final: production `kernel/plugins/context.ts` sudah mengganti query dari raw URL melalui firstValues sebelum validasi. Bare Elysia mengubah comma menjadi array, tetapi itu bukan boundary produksi repo ini. Diotorisasi menambah queryValues(url, allowedMultiKeys) pada hook existing: getAll raw hanya untuk enam key kategori di shared pure allow-list, scalar lain tetap first value, prototype-safe. Tidak ada plugin/route hook baru; JSON literal tetap nilai string literal, bukan format array alternatif. Developer wajib membuktikan comma/Unicode/repeats dan 400 sebelum guard pada pin 1.4.3/route nyata. Proposal singkat plural JSON-array lewat pesan dibatalkan setelah audit boundary ini; kontrak final tertulis tetap repeated key. Tidak ada dependency baru yang diperlukan. Developer memilih detail generics/helpers, tetap murni di lib/shared dan kontrak shared tanpa zod client.

Tradeoff: ini perubahan FE+kontrak/API, bukan sekadar mengganti radio menjadi checkbox atau memfilter page browser. Pemilik secara eksplisit meminta multiselect/auto-apply; perluasan kontrak kini diotorisasi, menggantikan pembatas scalar sebelumnya. Pertahankan bugfix/account-menu yang sudah dikerjakan; tidak mengulang setup atau provider work tanpa perubahan terkait.

Urutan: FIL-DES-002 dan FIL-API-001 paralel; FIL-DEV-002 mengikuti handoff desain per bagian/kontrak; FIL-QA-003 menyusun skenario sekarang, FIL-QA-004 memverifikasi kandidat terbaru. Developer mengestimasi **3,5–5 hari fokus** untuk FE+API/contract/tests+budget, menggantikan estimasi filter lama 1–2 hari; Designer/QA mengonfirmasi effort. Target skenario lokal dengan perubahan filter kini **12–18 hari kerja**, menggantikan 9–13 sebelumnya, kapasitas belum diketahui sehingga bukan komitmen. Prioritaskan rail/live multi sekarang; polish yang tidak menghalangi acceptance ditunda. Keputusan rilis tetap NO-GO sampai kandidat terbaru lulus dan Designer/QA mereview.

Klarifikasi final lintas role: **wire repeated singular keys; bukan plural JSON**. Search debounce 300 ms memakai **history replace**, checkbox (termasuk flush search) dan Clear all satu **history push**. Geometri Designer diterima: rail fixed 48 px dengan constant end clearance 64 px pada ≥md, expanded 320 px tanpa tambahan gutter; hasil identik closed/open. Desktop nonmodal, outside pointer/focus boleh melanjutkan aksi target sambil collapse tanpa mencuri fokus; phone launcher horizontal + modal sheet live. Ketentuan ini menggantikan pesan-pesan sementara yang saling menyilang sebelum audit production boundary.
